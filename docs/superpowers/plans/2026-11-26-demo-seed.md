# Demo Seed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a manually invoked TypeScript/Drizzle seed that creates a complete fictitious financial scenario for a demo account.

**Architecture:** A backend script imports the existing Drizzle schema/client and Argon2 package, inserts records in FK-safe order inside one transaction, and derives dates relative to its run date. It refuses production and exits without changes if the fixed demo email already exists.

**Tech Stack:** Node.js 26, TypeScript, Drizzle ORM, PostgreSQL, `@node-rs/argon2`.

**Spec:** `docs/superpowers/specs/2026-11-26-demo-seed-design.md`

## Global Constraints

- Keep the script manually invoked from `backend/` using the existing `.env` and `DATABASE_URL`.
- Do not modify migrations or schema.
- Never run in `NODE_ENV=production`.
- Use the fixed fictional email `demo@minifinance.local`; an existing row means a no-op with an explanatory message.
- Insert financial domain rows atomically and preserve all FK and financial invariants.
- Do not seed sessions; normal login creates the valid session.
- Keep existing frontend changes untouched.

## Review Focus

- Production environment: seed aborts before opening a DB connection.
- Duplicate demo email: seed exits successfully without writes.
- Invalid relational/financial seed data: transaction rolls back all inserted rows.
- São Paulo near month end: derive the current budget month from `APP_TIME_ZONE`, not the host's UTC date.
- Pending recurrence before its due day: set `nextExecutionOn` to the current month's occurrence; after it, use next month.
- Two seed processes at once: one insert wins and the other reports the existing account without writing data.
- Password: store only an Argon2 hash and make the demo credential available in the backend instructions.
